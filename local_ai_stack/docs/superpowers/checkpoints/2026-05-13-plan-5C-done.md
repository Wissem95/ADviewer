## Fonctionnalités livrées

### Backend (pipeline rigoureux désormais 8/11 stages opérationnels)

- **Stage2Challenge** (Gemini Pro) — avocat du diable. Identifie 3-5 risks,
  3-5 edge_cases, 1-2 alternatives, verdict severity, flag blocking. Émet
  `challenge_blocking` si jugé bloquant.
- **Stage4aPlan** (DeepSeek R1) — architecte planificateur. Produit
  `PlanResult(changes, tests_to_run, rollback_strategy, rationale,
  estimated_risk, complexity_confirm)`. Cite les facts de GROUND.
- **Stage4bPlanReview** (Gemini Pro) — reviewer indépendant. Verdict
  approve/revise/reject. Si revise, produit un `merged_plan` ajusté.
- **Stage4Consensus** wrapper — orchestre R1 + Pro sur 2 rounds max.
  - Round 1 : R1 produit → Pro review.
  - Si reject : Round 2 avec `retry_context.previous_review_concerns` injecté à R1.
  - Si toujours reject → deadlock, émet `consensus_disagreement` WS.
- **Stage6SelfCheck / Stage8Review / Stage9SecondReview** : stubs minimaux
  Plan 5C (success immédiat). Plan 5D les implémentera vraiment.
- **Pipeline.stages_by_mode** : trois modes complets :
  - SIMPLE (5 stages) — inchangé Plan 5A.
  - MEDIUM (8 stages) — ajoute plan + self_check + review.
  - COMPLEX (10 stages) — ajoute challenge + consensus + second_review.

### UI (Pipeline tab maintenant ultra-riche)

- **ChallengePanel** — affiche risks/edge_cases/alternatives + badge
  severity. Banner jaune avec boutons Continuer/Annuler si blocking.
- **PlanDiffView** — liste des changes avec icône par operation
  (edit ✎ / create + / patch △ / delete ✕), tests_to_run, rationale,
  badge risque tricolore.
- **DeadlockModal** — modal full-screen avec 2 PlanCards côte-à-côte
  (plan A vs plan B), concerns par round, boutons "Utiliser ce plan A/B"
  et "Annuler". Envoie `user_decision` via WS.
- **ConsensusRoundsLog** — log des rounds R1 ↔ Pro avec badges verdict
  tricolores (approve vert / revise orange / reject rouge), résumé plan
  (changes/tests/risque), concerns bullets.
- **pipelineStore** étendu : champs `challenge`, `challengeBlocking`,
  `plan`, `deadlock`, `consensusRounds[]` + actions
  `onChallengeResult`, `onChallengeBlocking`, `acknowledgeBlocking`,
  `onPlanResult`, `onDeadlock`, `resolveDeadlock`, `onConsensusRound`.
- 5 nouveaux listeners WS : `challenge_blocking`,
  `pipeline_user_decision_needed`, `consensus_round`.
